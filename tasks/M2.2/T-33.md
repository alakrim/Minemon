# T-33 — The ADMIN panel mod (minemon_admin)
ID / milestone / wave / risk: T-33 / M2.2 / wave 1 / medium (new mod, user-facing; uses other mods' public APIs)

## Goal and why
The owner wants an in-game admin panel to change the game live: capture harder/easier, spawn a creature in front of them, etc. (D-033). Build it as a new mod. Another worker (T-32) makes gameplay obey the knobs in parallel; you only build the UI and the actions.

## Read
CLAUDE.md, docs/CONVENTIONS.md, docs/DECISIONS.md D-033, mods/minemon/minemon_core/{tuning.lua, init.lua (end: minemon.tuning)}, mods/minemon/minemon_creatures/init.lua (`API.spawn`, `API.make_dread`, `API.get_instance`, `API.damage`, `API.is_owned`), mods/minemon/minemon_creatures/spawning.lua (`is_wild`), mods/minemon/minemon_capture/init.lua (`odds_target` raycast pattern, `catch` for how a creature joins the party, `give_balls` command), mods/minemon/minemon_party/init.lua (API: get, set, get_active, heal_all), mods/minemon/minemon_growth/init.lua (`API.grant_exp`), mods/minemon/minemon_lives/init.lua (`lives_give`, `lives_revive` commands and their local helpers), mods/minemon/minemon_sanctuary/init.lua (`API.list`), mods/minemon/minemon_core/data/items.json (item ids), an existing formspec in mods/minemon/minemon_party/ui.lua (style).

## What to build
`mods/minemon/minemon_admin/` with mod.conf (depends: minemon_core, minemon_creatures, minemon_party, minemon_capture, minemon_growth; optional: minemon_lives, minemon_sanctuary, minemon_dread, mcl_mobs), `init.lua` (glue), `admin_logic.lua` (pure: parsing and formspec string building, tested by busted).
- **Privilege** `minemon_admin`: `give_to_singleplayer = true`, `give_to_admin = true`. Every action and the command check it again on the server side (formspec fields can be forged).
- **`/admin`** opens the panel. Tabs (`tabheader`): **Tuning**, **Spawn**, **Player**, **World**. Size about 12×9. Dark style matching the party UI.
- **Tuning tab:** one row per key in `minemon.tuning.ORDER`, using `DEFS[key].label`: numbers get a field plus `−`/`+` buttons (one step); bools a checkbox; choices a dropdown. Quick presets: **Easy** (catch_mult 2, level_offset −5, exp_mult 2), **Normal** (reset), **Hard** (catch_mult 0.5, level_offset +10, dread_mult 2, exp_mult 0.75), **Nightmare** (catch_mult 0.3, level_offset +20, dread_mult 5, spawn_cap_mult 1.5). Show "(changed)" next to non-default values. Apply each change through `minemon.tuning.set`, then redraw.
- **Spawn tab:** species field (name like "pikachu" or dex number; use `minemon.data.get_species`, which accepts both; show an error line for unknown), level field (1–100, default 10), checkboxes **Dread**, **Shiny**, **Exhausted (ready to catch)**, **Give to me (party)**, count field (1–10). **Spawn** button: places creatures 3 nodes in front of the player (look dir flattened, on the first air node above ground), using `minemon.creatures.spawn(pos, id, level)`. Dread → `make_dread`; Shiny → set `le._mm.shiny = true` then re-apply visuals the same way the code does after activation (if there is no public way, set it in staticdata before spawning: read `API.spawn` and add an optional `opts` param ONLY if strictly needed, and say so in the report). Exhausted → deal damage equal to current HP via `minemon.creatures.damage(obj, hp, nil)`. Give to me → build an instance with `minemon.instance.new` and add it like capture's `catch` does (party if room, else PC, else error), owner set, ball "poke_ball", bond 70. Also a **Clear wild (32 nodes)** button (remove wild creatures with `mcl_util.remove_entity`), and **Exhaust target** (the wild creature you look at within 24 nodes, raycast like capture's `odds_target`).
- **Player tab:** Heal party, Give exp to active creature (field, default 1000, via `minemon.growth.grant_exp`), Give items (buttons: 10 of each ball incl. umbral, 500 coins `minemon:coin`, 10 potions, 1 of each evolution stone and the Link Cable, 10 Dread Shards; use item ids from items.json; skip unknown items quietly), Lives: +1 life and Revive (call the same code as `/lives_give` and `/lives_revive`: run the registered chatcommand's func via `core.registered_chatcommands[...]`, with the caller's own name).
- **World tab:** time buttons Dawn (0.25), Noon (0.5), Dusk (0.78), Midnight (0.0) via `core.set_timeofday`; Teleport to the nearest Sanctuary (from `minemon.sanctuary.list()`; skip if none); Toggle fly+fast+noclip privileges for yourself.
- Every action prints a short chat line to the admin ("[admin] Spawned 1 Pikachu Lv 10").

## Tests
- `tests/unit/admin_logic_spec.lua`: parsing of level/count/species fields (bounds, junk), preset tables, the formspec builder contains the tab names and a row per tuning key, escaping of user text.
- `tests/integration/admin/`: headless; call your action functions (expose them on `minemon.admin` for tests) with a fake or real player if available; at least: spawn 2 Rattata Lv 7 at a position → 2 entities with level 7; spawn with Exhausted → `is_exhausted`; preset Hard sets the knobs; Clear wild removes them. Follow tests/integration/dread for how suites get a player or none. (check.sh discovers suites by folder.)
- `bash scripts/check.sh` exits 0. If T-32 has not landed yet, tests must not depend on knob effects, only on knob values.
